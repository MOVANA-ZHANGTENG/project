# 部署文档（WCS）

本文档用于指导 **后端（Maven 打包 + 脚本启动）**、**前端（nginx 部署）**、**PDA（HBuilder 打包 APK）** 的部署与发布。

---

## 1. 环境准备

- **Java**：使用 **Java 1.8（JDK 1.8）**，配置好 `JAVA_HOME` 与 `PATH`
- **MySQL**：使用 **MySQL 5.7**
- **Maven**：3.5+，配置好 `MAVEN_HOME` 与 `PATH`
- **Node.js**：前端构建要求 **Node 14.18.1**（见 `wcs-ui/README.md`）
- **nginx**：用于前端静态资源发布 + API 反向代理
- **HBuilderX**：用于 PDA 应用打包 APK（uni-app / HTML5+）

---

## 2. 数据库部署（MySQL 5.7）

### 2.1 MySQL 初始化建议

- **字符集/排序规则**：建议 `utf8mb4` / `utf8mb4_general_ci`（或按你现场规范）
- **时区**：建议将 MySQL 与应用服务器时区统一（避免时间字段偏差）

### 2.2 创建库与导入 SQL

1. 创建数据库（示例）：

```sql
CREATE DATABASE deer_wcs DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

2. 导入建表/初始化脚本：
   - 以仓库内你实际提供的 `*.sql` 为准（如 `wms.sql`、`sql/` 目录下的脚本等）

### 2.3 应用数据库连接配置

后端数据库连接一般在以下位置（以实际为准）：

- `wcs-admin/src/main/resources/application.yml`
- 或环境专用配置（如 `wcs-admin/src/main/resources/application-*.yml`）

部署时请确保以下信息与现场一致：

- MySQL 主机/IP、端口（默认 3306）
- 数据库名、用户名、密码
- 连接参数（字符集、时区等）

## 2. 后端部署（Maven 打包）

### 2.1 Maven 打包

在后端工程根目录执行：

```bash
mvn clean package -DskipTests
```

打包产物通常为可执行 `jar`，本项目部署 **以 `wcs-admin.jar` 为准**。

---

## 3. 后端启动方式

本仓库提供两种启动脚本：

- Windows：`run.bat`
- Linux：`startUp.sh`

### 3.1 Windows 启动（run.bat）

`run.bat` 当前的启动方式要点：

- 启动文件：`wcs-admin.jar`
- JVM 参数：`-Xms256m -Xmx1024m -XX:MetaspaceSize=128m -XX:MaxMetaspaceSize=512m`
- 扩展加载路径：`-Dloader.path=resources,lib`
- 日志：自动写入 `logs/wcs-admin_YYYYMMDD_HHMMSS.log`（UTF-8）

部署建议目录结构（示例）：

```text
deploy/
  run.bat
  wcs-admin.jar
  resources/                 
  lib/                      
  logs/
```

启动步骤：

```bash
cd /d D:\project\deer_wcs\deploy
run.bat
```

验证：

- 查看控制台输出是否报错
- 查看 `logs/` 下最新日志文件
- 用浏览器/接口工具访问后端端口（以 `application.yml` 为准）

### 3.2 Linux 启动（startUp.sh）

`startUp.sh` 当前脚本的关键点（请注意 jar 名称）：

- 启动 `./wcs-admin.jar`，并指定 `--server.port=8007`
- 同时启动 `cmpp.jar`（如需要）
- `stop` 通过 `ps/grep` 查找 `wcs-admin.jar` 进程并 `kill -9`

 

赋权与启动：

```bash
chmod +x startUp.sh
./startUp.sh start
```

停止/重启：

```bash
./startUp.sh stop
./startUp.sh restart
```

注意事项：

- 本项目部署 **以 `wcs-admin.jar` 为准**。如果你的 `startUp.sh` 里仍是 `wms-admin.jar`，请将脚本中的 jar 名称同步改为 `wcs-admin.jar`，避免启动/停止时匹配不到进程。
- 端口 `8007` 仅为脚本当前写死值；若实际端口不同，请修改脚本或使用配置文件覆盖。

## 4. 前端部署（打包 + nginx）

### 4.1 前端打包

前端位于 `wcs-ui/`，构建命令如下（见 `wcs-ui/README.md`）：

```bash
# 安装依赖（首次）
npm install --registry=https://registry.npmmirror.com

# 构建测试环境
npm run build:stage

# 构建生产环境
npm run build:prod
```

构建产物通常在 `wcs-ui/dist/`。将 `dist` 目录内容复制到 nginx 静态目录（示例）：

- Linux：`/usr/share/nginx/html/wcs/`
- Windows：`nginx/html/wcs/`

### 4.2 nginx 配置（静态资源 + API 转发）

仓库已提供示例配置：

- `nginx.conf`：包含 `server { ... }` 示例
- `nginx-prod-api.conf`：可直接嵌入 `server` 的简化版

#### 4.2.1 API 转发规则（/prod_api -> /wcs）

当前示例的核心规则为：

- 前端请求：`/prod_api/...`
- 转发后端：`http://localhost:8007`
- 路径重写：`/prod_api/xxx` 重写为 `/wcs/xxx`

将以下配置放到 nginx 的 `server` 块中（可参考 `nginx-prod-api.conf`）：

```nginx
location /prod_api {
    proxy_pass http://localhost:8007;
    rewrite ^/prod_api/(.*)$ /wcs/$1 break;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 60s;
    proxy_send_timeout 60s;
    proxy_read_timeout 60s;
}
```

> 如后端地址、端口、上下文路径（`/wcs`）不同，请按实际调整 `proxy_pass` 与 `rewrite`。

#### 4.2.2 前端静态资源（Vue SPA 常用写法）

如需 nginx 直接托管前端并支持前端路由（history 模式），可参考：

```nginx
location / {
    root /usr/share/nginx/html/wcs;
    index index.html;
    try_files $uri $uri/ /index.html;
}
```

#### 4.2.3 nginx 生效

```bash
nginx -t
nginx -s reload
```

## 5. PDA 部署（HBuilder 打包 APK）

### 5.1 打包流程（HBuilderX）

1. 使用 HBuilderX 打开 PDA 工程（uni-app / HTML5+）
2. 配置生产环境接口地址（建议指向 nginx 对外地址，例如：`http(s)://<域名或IP>/prod_api/`）
3. 选择菜单：**发行** → **原生 App-打包**（云打包或本地打包）
4. 配置包名、版本号、图标、签名证书（正式包建议使用正式签名）
5. 生成 `apk` 文件

### 5.2 安装与验证

1. 将 APK 传到 PDA 设备并安装（必要时开启“允许未知来源”）
2. 验证关键流程：登录、扫码、任务执行等

重要约束：

- **前端字段名/接口返回字段不要凭空猜测**，必须以 **后端接口返回** 为准后再对接与发布。

---

## 6. 发布检查清单（建议）

- **后端**
  - `jar` 与脚本引用名称一致（以 `wcs-admin.jar` 为准）
  - 端口与配置一致（Linux 脚本当前默认 `8007`）
  - 日志目录/权限正常
- **前端**
  - 使用 `npm run build:prod` 打生产包
  - nginx 已配置静态目录与 `/prod_api` 转发
  - `/prod_api` 路径重写与后端上下文 `/wcs` 对齐
- **PDA**
  - APK 版本号更新
  - API 地址指向生产环境 nginx
  - 关键功能现场验证通过
