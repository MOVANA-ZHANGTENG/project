# 层叠上下文问题修复说明

## 🐛 问题根源

### 发现的真正问题
之前的z-index调整虽然正确，但没有解决根本问题：

```scss
.container3d {
  position: relative;  // 👈 创建了层叠上下文
}
```

**关键点**：
- `.container3d`设置了`position: relative`，创建了一个**层叠上下文（Stacking Context）**
- 层叠上下文内的所有元素，无论z-index多高，都无法突破这个上下文
- Header、Left、Bottom在index.vue中，它们的z-index:10会覆盖整个container3d

### 层叠关系图

```
body
├─ index.vue (container)
│   ├─ Three3d (z-index:0) 
│   │   └─ container3d (position:relative) ← 创建层叠上下文
│   │       └─ 调试面板 (z-index:100) ← 被困在container3d内
│   │       └─ 无人机UI (z-index:120) ← 被困在container3d内
│   │
│   ├─ Header (z-index:10) ← 覆盖整个container3d ✅
│   ├─ Left (z-index:10)
│   └─ Bottom (z-index:10)
```

结果：即使调试面板的z-index是100，它仍然被z-index:10的Header遮挡！

---

## ✅ 解决方案：Teleport

### Vue 3 Teleport 原理

使用`<Teleport>`将组件传送到DOM的其他位置，突破层叠上下文限制：

```vue
<template>
  <div class="container3d">
    <!-- 3D画布 -->
  </div>
  
  <!-- 🚀 使用Teleport传送UI到body -->
  <Teleport to="body">
    <div class="control-panel">...</div>
    <div class="drone-crosshair">...</div>
  </Teleport>
</template>
```

### 改造后的结构

```
body
├─ 模型加载进度 (teleport, z-index:999) ✅ 最顶层
├─ 调试控制面板 (teleport, z-index:100) ✅ 不被遮挡
├─ 堆垛机面板 (teleport, z-index:110) ✅ 不被遮挡
├─ 无人机UI (teleport, z-index:120) ✅ 不被遮挡
│
└─ #app (container)
    ├─ Three3d (z-index:0)
    ├─ Header (z-index:10)
    ├─ Left (z-index:10)
    └─ Bottom (z-index:10)
```


## 📊 Teleport的UI组件

### 被传送的组件列表

| 组件 | 原位置 | 新位置 | z-index |
|------|--------|--------|---------|
| `.progress-box` | container3d | body | 999 |
| `.control-panel.panel-debug` | container3d | body | 100 |
| `.stacker-info-panel` | container3d | body | 110 |
| `.drone-crosshair` | three-canvas | body | 120 |

### 样式要求

所有被teleport的组件必须使用**fixed**或**absolute**定位：

```scss
.control-panel {
  position: absolute; // 或 fixed ✅
  z-index: 100;
  top: 20px;
  right: 20px;
}

.drone-crosshair {
  position: absolute; // 或 fixed ✅
  z-index: 120;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
}
```

## 💡 Teleport 注意事项

### 1. 事件处理

Teleport的组件虽然DOM被移动了，但**事件处理仍然绑定在原组件上**：

```vue
<Teleport to="body">
  <div @click="handleClick">  <!-- ✅ 事件正常工作 -->
    点击我
  </div>
</Teleport>
```

### 2. 响应式数据

Teleport的组件仍然可以**访问父组件的数据和方法**：

```vue
<Teleport to="body">
  <div>{{ someData }}</div>  <!-- ✅ 响应式正常 -->
</Teleport>
```

### 3. CSS作用域

如果使用`<style scoped>`，样式仍然会应用到teleport的组件：

```vue
<style scoped>
.control-panel {
  /* ✅ 这个样式会应用到teleport的元素 */
}
</style>
```

### 4. 条件渲染

Teleport支持条件渲染，不会影响性能：

```vue
<Teleport to="body">
  <div v-if="show">...</div>  <!-- ✅ 正常工作 -->
</Teleport>
```

## 🔄 对比其他方案

### 方案1：提高container3d的z-index ❌
```scss
.container3d {
  position: relative;
  z-index: 1000;  // 提高整个容器
}
```
**问题**：会导致整个3D场景覆盖Header/Left/Bottom

### 方案2：移除container3d的定位 ❌
```scss
.container3d {
  // position: relative;  移除
}
```
**问题**：可能影响内部元素的定位和布局

### 方案3：使用Portal库 ⚠️
```javascript
import { createPortal } from 'react-dom';
```
**问题**：Vue 3原生支持Teleport，不需要额外库

### 方案4：Teleport ✅
```vue
<Teleport to="body">...</Teleport>
```
**优势**：
- ✅ 完全突破层叠上下文
- ✅ Vue 3原生支持
- ✅ 不影响原有逻辑
- ✅ 性能优秀

## 🐛 可能的问题

### Q1: Teleport后元素位置错乱？

**原因**：元素使用了相对定位
**解决**：改为绝对或固定定位

```scss
// ❌ 错误
.control-panel {
  position: relative;
  left: 20px;
}

// ✅ 正确
.control-panel {
  position: fixed;
  top: 20px;
  right: 20px;
}
```

### Q2: Teleport的元素不显示？

**原因**：target元素不存在或未挂载
**解决**：确保target存在

```vue
<!-- ✅ 正确：body始终存在 -->
<Teleport to="body">...</Teleport>

<!-- ⚠️ 可能问题：#modal可能不存在 -->
<Teleport to="#modal">...</Teleport>
```

### Q3: 事件处理失效？

**原因**：可能是事件冒泡被阻止
**解决**：检查事件处理

```vue
<Teleport to="body">
  <!-- ✅ 事件正常工作 -->
  <div @click.stop="handleClick">...</div>
</Teleport>
```

## 📝 总结

### 问题本质
不是z-index的数值问题，而是**层叠上下文**的隔离问题。

### 解决思路
1. 识别创建层叠上下文的元素
2. 使用Teleport将UI传送到外层
3. 保持正确的z-index值

### 关键要点
```
层叠上下文 > z-index数值
```

无论z-index多大，都无法跨越层叠上下文。使用Teleport是最优雅的解决方案。
