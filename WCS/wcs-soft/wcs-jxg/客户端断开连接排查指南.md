# 客户端断开连接问题排查指南

## 问题描述

**错误日志：**
```
ZkCarUtil - [lambda$run$1,122] - ❌ 客户端断开: ClientInfo{id='192.168.1.171', address=192.168.1.171:47976, connected=38963ms}, 原因: 连接关闭
```

**关键信息：**
- 客户端IP：`192.168.1.171`
- 连接端口：`47976`
- 连接时长：`38963ms`（约39秒）
- 断开原因：`连接关闭`

---

## 原因分析

### 1. 客户端主动断开（最可能）

**触发位置：** `RcsTcpServer.java` 第270-284行

```java
while (connected && (line = reader.readLine()) != null) {
    // 处理消息...
}
// 当 readLine() 返回 null 时，表示客户端关闭了连接
```

**可能情况：**
- ✅ 客户端程序正常退出
- ✅ 客户端程序异常崩溃
- ✅ 客户端网络断开
- ✅ 客户端进程被杀死

**排查方法：**
1. 检查客户端（智库小车控制器）日志
2. 查看客户端是否有异常退出记录
3. 检查客户端网络是否稳定

---

### 2. 心跳超时（次要可能）

**心跳配置：** `RcsTcpServer.java` 第29-30行

```java
private static final long HEARTBEAT_INTERVAL = 30 * 1000; // 30秒检测一次
private static final long HEARTBEAT_TIMEOUT = 60 * 1000;  // 60秒超时
```

**分析：**
- 连接时长：39秒
- 超时时间：60秒
- **结论：** 未达到心跳超时时间，所以不是心跳超时导致

**但需要注意：**
如果客户端在39秒内没有发送任何消息（包括状态上报、事件上报等），下一次心跳检测（第60秒）时就会断开连接。

---

### 3. 网络不稳定

**可能情况：**
- 网络中断
- 路由器/交换机故障
- IP冲突
- 防火墙拦截

**排查方法：**
```bash
# 1. 检查网络连通性
ping 192.168.1.171

# 2. 检查是否有网络丢包
ping -t 192.168.1.171

# 3. 检查路由跟踪
tracert 192.168.1.171

# 4. 检查端口是否开放
telnet 192.168.1.171 852
```

---

### 4. 同IP重复连接

**触发位置：** `RcsTcpServer.java` 第97-103行

```java
// 检查同IP是否已存在连接，如果存在则关闭旧连接
ClientHandler existingClient = clients.get(clientId);
if (existingClient != null) {
    System.out.println("检测到同IP重复连接，关闭旧连接: " + clientId);
    existingClient.close("同IP新连接建立");
}
```

**排查方法：**
检查日志中是否有 "检测到同IP重复连接" 的记录


3. **连接断开前：**
```
⚠️ 客户端关闭了连接流: 192.168.1.171, 连接时长: XXXms
❌ 客户端断开: ClientInfo{...}, 原因: 连接关闭
```

### 第二步：分析断开模式

#### 情况A：定时断开（例如每隔固定时间断开）
- **可能原因：** 客户端有定时重连机制
- **解决方案：** 检查客户端配置，优化重连策略

#### 情况B：无规律断开
- **可能原因：** 网络不稳定或客户端异常
- **解决方案：** 检查网络和客户端程序

#### 情况C：心跳超时前断开（距上次心跳 > 50秒）
- **可能原因：** 客户端停止发送消息
- **解决方案：** 客户端需要定期发送状态数据

### 第三步：检查客户端消息频率

查看客户端（智库小车）是否定期发送以下消息：

1. **状态消息（StateRequestMsg）**
   - 建议频率：每5-10秒
   - 用途：上报位置、电量、速度等遥测数据

2. **事件消息（EventSendMsg）**
   - 频率：按需发送
   - 用途：上报初始化、任务阶段等事件

**如果客户端长时间不发送消息，会触发心跳超时！**

## 常见问题 FAQ

### Q1：为什么连接39秒就断开了？

**A：** 从日志看，是客户端主动关闭了连接（`reader.readLine()` 返回 `null`），可能原因：
1. 客户端程序设计问题（定时重连？）
2. 客户端程序崩溃
3. 网络断开

### Q2：心跳超时是60秒，为什么39秒就断开了？

**A：** 不是心跳超时导致的断开，而是客户端主动断开。现在日志会区分这两种情况：
- 心跳超时：`❌ 客户端心跳超时`
- 客户端断开：`⚠️ 客户端关闭了连接流`

### Q3：如何确认是客户端问题还是服务端问题？

**A：** 查看以下信息：
1. 服务端日志显示 `⚠️ 客户端关闭了连接流` → **客户端主动断开**
2. 服务端日志显示 `❌ 客户端心跳超时` → **客户端长时间未发送消息**
3. 服务端日志显示 `IO异常` → **网络问题**

### Q4：客户端应该多久发送一次消息？

**A：** 建议：
- **状态消息（StateRequestMsg）：** 每5-10秒
- **确保任何消息间隔不超过50秒**（避免心跳超时）
